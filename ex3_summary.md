### Тесты по пунктам

- **№1 (инъекция):** `status = x' OR '1'='1`, `'; DROP TABLE orders; --`, `UNION SELECT` → запрос содержит плейсхолдер, значение передано аргументом, выборка не расширяется; легитимный статус возвращает только свои строки.
- **№2 (rows):** `rows.Close()` вызывается на всех путях; ошибка `rows.Err()` возвращается; happy path отдаёт ожидаемый JSON.
- **№3 (валидация):** отсутствующий `status` → `400`; неизвестный статус → `400`; валидный статус → `200`.
- **№4 (ошибки):** ошибка `QueryContext` → обёрнутая ошибка в логе и `500`; текст БД не попадает в тело ответа.
- **№5 (контекст):** отмена `r.Context()` → запрос прерывается, ошибка маппится по контракту проекта.

### План действий

1. **До merge:** закрыть №1–3 (параметризация запроса, закрытие `rows`, валидация `status`).
2. **В этом же PR, если дёшево:** №4 (обёртка ошибки + лог + `500`).
3. **Отдельные тикеты:** единый контракт ошибок и маппинг в HTTP-коды, политика `Context`/таймаутов, вынос SQL в слой репозитория.
